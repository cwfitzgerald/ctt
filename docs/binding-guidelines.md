# Binding Crate Guidelines

This document describes the patterns and conventions used by the `ctt-*` binding crates that wrap third-party texture compression libraries. It serves two purposes:

1. **For contributors** adding new bindings — follow these guidelines to keep the codebase consistent.
2. **For readers** trying to understand how existing bindings work.

## Existing binding crates

| Crate | Upstream library | Language | Build tool |
|---|---|---|---|
| `ctt-astcenc` | [ARM astcenc](https://github.com/ARM-software/astc-encoder) | C++ | `cc` |
| `ctt-bc7enc-rdo` | [bc7enc_rdo](https://github.com/richgel999/bc7enc_rdo) | ISPC | `ispc-build-utils` |
| `ctt-intel-texture-compressor` | [ISPCTextureCompressor](https://github.com/GameTechDev/ISPCTextureCompressor) | ISPC | `ispc-build-utils` |

## Crate layout

Every binding crate follows this directory structure:

```
crates/ctt-<name>/
├── Cargo.toml
├── build.rs
├── vendor.sh                     # copies vendored source from an external checkout
├── src/
│   ├── lib.rs                    # safe Rust API + module roots
│   ├── bindings.rs               # (single file) auto-generated by bindgen
│   └── bindings/                 # (multiple files) auto-generated by bindgen
│       └── <name>.rs             # DO NOT EDIT — use cargo xtask generate-bindings
├── cpp/ or ispc/                 # vendored upstream source
├── LICENSE-<SPDX>-<UPSTREAM>.md  # upstream license file(s)
├── prebuilt/                     # (ISPC only) prebuilt binary sub-crate
│   ├── Cargo.toml
│   ├── build.rs
│   ├── src/lib.rs
│   └── bins/<platform>/          # static libs + sigstore attestations
└── ...
```

Use `src/bindings.rs` when there is a single generated file. Use a `src/bindings/` directory with an inline `mod bindings {}` in `lib.rs` when there are multiple generated files.

## Naming conventions

### Crate name

All binding crates **must** use the `ctt-` prefix:

```
ctt-<upstream-library-name>
```

Use the upstream project's common short name.

### Prebuilt sub-crate

If the crate has prebuilt binaries, the sub-crate is named:

```
ctt-<upstream-library-name>-prebuilt
```

### Cargo.toml metadata

Use workspace inheritance for `version`, `edition`, `repository`, `rust-version`, and `readme`. Set `authors` to include both `"The ctt developers"` and the upstream author(s). The `license` field should be a compound SPDX expression covering both the crate wrapper and the vendored code:

```toml
license = "(MIT OR Apache-2.0 OR Zlib) AND <upstream-license>"
```

Use `links = "<lib_name>"` when the crate produces a native static library, to prevent duplicate linking.

## Vendored source

### What gets vendored

Only the files needed to compile the library. Exclude CLI tools, test suites, build system files (CMake, Makefiles), and documentation from the upstream project.

### vendor.sh

Each crate has a `vendor.sh` script that copies source files from a local checkout of the upstream repository. The script:

- Takes an optional argument for the source directory (defaults to `../../../<upstream-repo>/...`).
- Validates the source directory exists.
- Clears the destination directory (`cpp/` or `ispc/`) and copies fresh files.
- Copies the upstream license file into the crate root as `LICENSE-<SPDX>-<NAME>.md`.

### Vendored source directory naming

| Source language | Directory |
|---|---|
| C / C++ | `cpp/` |
| ISPC | `ispc/` |

## Bindings generation

All FFI bindings are generated by `bindgen` and regenerated via:

```sh
cargo xtask generate-bindings
```

The generated files are checked into the repository so that users don't need `bindgen` or `libclang` to build. Each generated file starts with a header comment:

```rust
// Generated by bindgen — regenerate with `cargo xtask generate-bindings`.
//
// Source: <relative path to header/ispc file>
#![allow(non_camel_case_types, non_snake_case, dead_code)]
```

### What goes in generated bindings

- `#[repr(C)]` struct definitions
- Constants and enum values
- `unsafe extern "C"` function declarations (when symbols are not renamed)

### What does NOT go in generated bindings

- Safe Rust wrappers — those belong in `lib.rs` or dedicated modules.
- Hand-written `extern "C"` blocks for renamed symbols (e.g. ISA-prefixed symbols in `ctt-astcenc`) — those belong elsewhere.

### Bindings module structure

**Single binding file** — use a flat `src/bindings.rs`:

```rust
// src/lib.rs
mod bindings;
pub use bindings::*;  // re-export types and constants
```

**Multiple binding files** — use an inline `mod bindings` in `lib.rs` with files in a `src/bindings/` directory:

```rust
// src/lib.rs
pub mod bindings {
    pub mod kernel;
    pub mod other;
}
```

The safe API imports from the bindings module:

```rust
use crate::bindings::kernel;
// then: kernel::SomeStruct, kernel::some_function(...)
```

### ISPC-specific bindgen notes

For ISPC crates, the `xtask generate-bindings` command:

1. Compiles the `.ispc` file at `-O0` to produce an `_ispc.h` header.
2. Runs `bindgen` on the generated header with `-std=c11` and `-include stdbool.h`.
3. Uses `allowlist_function` / `allowlist_type` to control what's exposed.

If the ISPC header contains anonymous struct names like `$anon0`, rename them before running bindgen (see `rename_ispc_anon_structs` in `xtask/src/generate_bindings.rs`).

## Build system

### C/C++ libraries (using `cc`)

For C/C++ upstream libraries, use the `cc` crate in `build.rs`. Key conventions:

- Use `cc::Build` to compile vendored source files.
- Set the appropriate language standard (e.g. `.std("c++14")`).
- Disable warnings with `.warnings(false)` — upstream code is not ours to fix.
- Use `cargo:rerun-if-changed=<source-dir>` for incremental rebuild correctness.
- Use `cc` with the `"parallel"` feature for faster builds.

Example (`build.rs`):

```rust
fn main() {
    println!("cargo:rerun-if-changed=cpp");

    let mut build = cc::Build::new();
    build
        .cpp(true)
        .std("c++14")
        .include("cpp")
        .warnings(false);

    for source in SOURCES {
        build.file(source);
    }

    build.compile("mylib");
}
```

### ISPC libraries (using `ispc-build-utils`)

For ISPC upstream libraries, use the workspace's `ispc-build-utils` crate, which wraps the ISPC compiler and handles multi-target compilation (SSE2, SSE4, AVX, AVX2 on x86_64; NEON on aarch64).

The `build.rs` for ISPC crates is very short:

```rust
fn main() {
    #[cfg(all(feature = "prebuilt", feature = "build-from-source"))]
    compile_error!("features `prebuilt` and `build-from-source` are mutually exclusive");

    #[cfg(feature = "build-from-source")]
    {
        let mut config = ispc_build_utils::Config::new();
        config
            .file("ispc/kernel.ispc")
            .opt_level(2)
            .woff()
            .fast_math()
            .disable_assertions();
        config.compile("kernel");
    }
}
```

### ISPC prebuilt binaries

ISPC crates ship prebuilt static libraries so users don't need the ISPC compiler. This is implemented as a separate sub-crate (`ctt-<name>-prebuilt`) with:

- A `bins/` directory containing platform-specific `.a`/`.lib` files and sigstore attestation files.
- A `build.rs` that calls `ispc_build_utils::prebuilt::link_prebuilt(...)`.
- `links = "<lib_name>"` in `Cargo.toml`.

Two mutually exclusive features control which path is used:

| Feature | Default | Description |
|---|---|---|
| `prebuilt` | Yes | Links against prebuilt static libraries. No compiler needed. |
| `build-from-source` | No | Compiles from ISPC source. Requires ISPC on `PATH`. |

For full details on how prebuilt binaries are produced, attested, and verified, see [prebuilt-binaries.md](prebuilt-binaries.md).

**Prebuilt binaries are only used for ISPC crates or other exotic compilers.** C/C++ crates that use `cc` build from source every time — the C/C++ compiler is a standard part of the Rust toolchain's build environment.

### Prebuilt sub-crate layout

```
prebuilt/
├── Cargo.toml          # links = "<lib_name>", includes bins/**
├── build.rs            # ispc_build_utils::prebuilt::link_prebuilt(&["<lib>"])
├── src/lib.rs          # empty (linking-only crate)
└── bins/
    ├── linux-x86_64/
    │   ├── lib<name>.a
    │   └── lib<name>.a.sigstore.jsonl
    ├── linux-aarch64/
    ├── macos-x86_64/
    ├── macos-aarch64/
    ├── windows-x86_64/
    │   ├── <name>.lib
    │   └── <name>.lib.sigstore.jsonl
    └── windows-aarch64/
```

The main crate activates the prebuilt dependency with a feature-gated `extern crate`:

```rust
// src/lib.rs
#[cfg(feature = "prebuilt")]
extern crate ctt_my_lib_prebuilt;
```

## Safe Rust API

The most important layer. All binding crates expose a safe public API that hides the `unsafe` FFI boundary.

### Design principles

1. **No `unsafe` in public API.** All unsafe code is confined to the crate internals.
2. **Validate inputs before crossing the FFI boundary.** Check dimensions, buffer sizes, and invariants that the C API requires.
3. **Use `Result` for fallible operations.** If the C library returns error codes, wrap them in a proper error type. Use `thiserror` for error definitions.
4. **Use RAII for resource management.** If the C library has alloc/free pairs, wrap them in a struct with a `Drop` impl.
5. **Minimize allocations on the hot path.** Provide both an allocating convenience function and an `_into` variant that writes to a caller-provided buffer.
6. **Mark pure output functions with `#[must_use]`.**

### Error handling

When the upstream C API returns error codes, define a proper error type using `thiserror`:

```rust
#[derive(Debug, Clone, thiserror::Error)]
#[error("astcenc error: {message}")]
pub struct Error {
    code: ffi::error_code,
    message: String,
}
```

Convert C error codes to `Result` at the FFI boundary:

```rust
fn check(code: ffi::error_code) -> Result<(), Error> {
    if code == ffi::SUCCESS {
        Ok(())
    } else {
        Err(Error {
            code,
            message: get_error_string(code),
        })
    }
}
```

When the upstream API is infallible (e.g. ISPC compression functions that can't fail given valid inputs), use `assert!` / `panic!` for input validation rather than returning `Result`. The caller broke the contract — panicking is appropriate.

### Compression function pattern

Most binding crates expose block compression. Use this consistent pattern:

```rust
/// Returns the compressed output size in bytes for the given image dimensions.
#[must_use]
pub fn calc_output_size(width: u32, height: u32) -> usize {
    let block_count = (width.div_ceil(4) * height.div_ceil(4)) as usize;
    block_count * BYTES_PER_BLOCK
}

/// Compresses the surface, returning a newly allocated `Vec<u8>`.
#[must_use]
pub fn compress_blocks(surface: &MySurface) -> Vec<u8> {
    let mut output = vec![0u8; calc_output_size(surface.width, surface.height)];
    compress_blocks_into(surface, &mut output);
    output
}

/// Compresses the surface into a caller-provided buffer.
///
/// # Panics
///
/// Panics if `blocks.len()` does not equal `calc_output_size(...)`.
pub fn compress_blocks_into(surface: &MySurface, blocks: &mut [u8]) {
    assert_eq!(blocks.len(), calc_output_size(surface.width, surface.height));
    // ... unsafe FFI call ...
}
```

### RAII wrappers

When the C library has an alloc/free lifecycle, wrap it in a struct:

```rust
pub struct Context {
    ptr: *mut ffi::context,
}

unsafe impl Send for Context {}
// Only impl Sync if the C library is thread-safe for concurrent reads.

impl Context {
    pub fn new(config: &Config) -> Result<Self, Error> {
        let mut ptr = std::ptr::null_mut();
        check(unsafe { ffi::context_alloc(config, &mut ptr) })?;
        Ok(Self { ptr })
    }
}

impl Drop for Context {
    fn drop(&mut self) {
        if !self.ptr.is_null() {
            unsafe { ffi::context_free(self.ptr) };
        }
    }
}
```

Document `Send`/`Sync` impls with `// SAFETY:` comments explaining why they are sound.

### Initialization guards

Some C libraries require a one-time init call before use. Guard it with `Once` or `OnceLock`:

```rust
use std::sync::Once;

static INIT: Once = Once::new();

fn ensure_init() {
    INIT.call_once(|| unsafe {
        ffi::codec_init();
    });
}
```

Call `ensure_init()` at the start of every public function that touches the FFI.

### Settings / parameters

When the upstream library has a settings struct with many fields, create a Rust-side settings type with idiomatic field names (snake_case) and provide preset constructor functions:

```rust
pub struct EncodeSettings {
    pub mode_selection: [bool; 4],
    pub refine_iterations: [u32; 8],
    // ...
}

pub fn ultra_fast_settings() -> EncodeSettings { /* ... */ }
pub fn slow_settings() -> EncodeSettings { /* ... */ }
```

Convert to the C struct only at the FFI boundary, inside the `compress_blocks_into` function.

## Thread safety

Carefully consider the upstream library's threading model:

- If the library has no internal mutable state after initialization: `Send + Sync`.
- If the library mutates internal state during calls: `Send` only (require `&mut self`).
- If the library is not thread-safe at all: neither `Send` nor `Sync`.

Document the rationale with `// SAFETY:` comments on any manual `Send`/`Sync` impls.

## Testing

At minimum, include a basic smoke test that compresses a single block and verifies non-trivial output:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn compress_single_block() {
        let pixels = [0xFF0000FFu32.to_le(); 16]; // solid red, RGBA
        let params = params_ultrafast();
        let mut output = [0u8; 16];
        compress_blocks_into(&pixels, &mut output, &params);
        assert!(output.iter().any(|&b| b != 0), "expected non-zero output");
    }
}
```

## Checklist for adding a new binding crate

- [ ] Crate is named `ctt-<name>` under `crates/`.
- [ ] `vendor.sh` copies only necessary source files and the upstream license.
- [ ] Upstream license file is at `LICENSE-<SPDX>-<NAME>.md` in the crate root.
- [ ] `Cargo.toml` has compound `license`, workspace-inherited fields, and `links` if applicable.
- [ ] Vendored source is in `cpp/` (C/C++) or `ispc/` (ISPC).
- [ ] Bindings are generated via `cargo xtask generate-bindings` and checked in.
- [ ] Generated bindings are in `src/bindings.rs` (single file) or `src/bindings/<name>.rs` (multiple files).
- [ ] `build.rs` compiles vendored source (using `cc` for C/C++, `ispc-build-utils` for ISPC).
- [ ] (ISPC only) Prebuilt sub-crate exists at `prebuilt/` with `prebuilt`/`build-from-source` features.
- [ ] (ISPC only) Features are mutually exclusive with a `compile_error!` guard.
- [ ] Safe Rust API in `src/lib.rs` or dedicated modules — no `unsafe` in public signatures.
- [ ] Fallible C APIs return `Result<T, Error>` with a `thiserror` error type.
- [ ] RAII wrapper with `Drop` for any alloc/free lifecycle.
- [ ] `Send`/`Sync` impls have `// SAFETY:` justification.
- [ ] At least one smoke test that compresses a block.
- [ ] `generate-bindings` entry added to `xtask/src/generate_bindings.rs`.
